# Vue Web 应用

## 职责

前端使用 Vue 3 Composition API、TypeScript 和 Vite。它负责查询条件、K 线与指标展示、回测表单、结果摘要和历史列表，不在浏览器计算聚合、Stoch 或回测信号。

## M1 页面结构

单页工作台采用三段式布局：

1. 顶部状态栏：产品名、BTCUSD、数据覆盖范围和服务状态。
2. 主工作区：时间范围/周期工具栏、K 线图、Stoch 副图和 OHLC 表格替代视图。
3. 回测侧栏：策略参数、提交状态、结果指标和最近记录。

桌面宽度大于等于 `1024px` 时主图与侧栏并排；小屏幕按行情、参数、结果顺序垂直排列。页面不得产生横向滚动。

## 图表约定

- K 线同时使用实体形态和涨跌颜色，不能只依赖红绿表达方向。
- 默认最多渲染 500 根，接口硬上限 5,000 根；超过可视密度时只请求或显示选定范围。
- Stoch 显示 K/D 图例及 20、50、80 参考线。
- 鼠标悬停和键盘聚焦显示相同 OHLC 值。
- 图表下方提供最近 K 线表格，作为屏幕阅读器和无 Canvas 场景的替代。
- 时间轴、表格和表单一律标记 UTC。

## 状态管理

M1 不引入全局状态库。页面使用组合式函数分别管理：

- `market`：元数据、筛选条件、快照、加载和错误状态。
- `backtests`：表单、提交状态、当前结果和历史记录。
- `health`：入口与两个后端的可用性提示。

筛选条件保存在 URL 查询参数，以便刷新和分享。策略表单草稿保存在浏览器本地；已保存配置和回测结果以服务端为准。

## 交互与可访问性

- 所有输入使用可见 `label`，错误显示在对应字段附近。
- 异步提交期间禁用按钮并显示明确进度；失败信息包含原因和重试操作。
- 所有按钮可通过键盘操作，焦点环清晰；触控目标至少 `44×44px`。
- 正文对比度至少 `4.5:1`，数据线和控件边界至少 `3:1`。
- 遵循 `prefers-reduced-motion`，不使用阻塞式或纯装饰动画。
- 页面提供跳到主要内容的链接，标题层级连续，状态更新使用礼貌型 live region。

## API 访问

浏览器只使用同源相对路径 `/api/...`，不感知容器名或内部端口。前端不得持有 PostgreSQL、行情服务或回测服务凭据。

# Windows 客户端迁移

## 原则

旧 Win32/C++ 客户端是迁移期间的行为基准，保存在 `legacy/windows-desktop/`。在功能等价验收完成前不删除源码、构建说明或可迁移的数据格式；新系统也不继续把 C++ 模块当作运行时依赖。

## 功能迁移矩阵

| 旧功能 | 新归属 | 里程碑 | 验收方式 |
| --- | --- | --- | --- |
| CSV/内嵌 1m 行情 | Parquet + market-data | M1 | 条数、时间和 OHLC 抽样一致 |
| 9 个周期聚合 | market-data | M1 | 固定边界样本逐根对比 |
| 三组 Stoch | market-data | M1 | 与 C++/Pine 基准误差内一致 |
| K 线与副图 | Vue | M1 | 桌面/移动端与表格替代视图 |
| 日期定位/范围选择 | Vue + market API | M1 | UTC 边界和空区间 |
| 参数保存 | backtest + PostgreSQL | M1 | 重启后配置仍存在 |
| 策略回测与历史 | backtest + PostgreSQL | M1 | 固定数据产生确定性结果 |
| 播放/暂停/单步/倍速 | replay 服务 + Vue | M2 | 与旧客户端时间推进一致 |
| 项目/回放进度 | replay 服务 + PostgreSQL | M2 | 导入后可继续播放 |
| 趋势线和 Buy/Sell 标记 | replay 服务 + Vue | M2 | 时间与价格坐标保持 |
| 多窗口周期联动 | Web 多面板/标签页 + replay | M2 | 同一 UTC 游标一致 |
| 快捷键 | Vue | M2 | 不覆盖浏览器/辅助技术快捷键 |

## 行情迁移

旧内嵌 CSV 的每行转换为 Parquet 六列。旧数据没有 volume 时不得伪造交易量；迁移工具应写 `0` 并在 `manifest.json` 标记 `volume_available=false`。转换后必须比较：

- 输入有效行数与输出行数。
- 第一/最后时间戳、缺失分钟数和重复数。
- 至少 100 个固定或随机位置的 OHLC。
- 9 个周期的桶边界和聚合结果。
- 三组 Stoch 的首个有效位置与数值误差。

## 项目文件迁移

`.replay` 文件迁移属于 M2。迁移器只读旧文件并输出导入报告；原文件不原地修改。无法映射的窗口位置、快捷键或损坏记录作为 warning 记录，核心时间范围、播放游标、指标参数、趋势线和标记无法迁移时该项目整体失败。

## 切换与回滚

1. M1 上线后并行保留旧客户端，重点验证行情与指标。
2. M2 在复制的项目数据上完成导入和回放等价测试。
3. 用户确认关键项目后，新系统成为默认入口，旧客户端进入只读维护。
4. 至少保留一个发布周期后再决定移除旧构建产物。

回滚只改变默认入口和应用版本，不回写或删除旧项目文件。

# Parquet 行情数据规范

## 文件约定

M1 使用单文件 `/data/btcusd_1m.parquet`，容器内只读。文件内容必须按 `timestamp` 升序排列且时间戳唯一。

| 列 | Parquet 逻辑类型 | 单位 | 规则 |
| --- | --- | --- | --- |
| `timestamp` | INT64 | Unix UTC 秒 | 1 分钟桶开始时间，非空 |
| `open` | DOUBLE | USD | 非空、有限正数 |
| `high` | DOUBLE | USD | `>= max(open, close, low)` |
| `low` | DOUBLE | USD | `<= min(open, close, high)` |
| `close` | DOUBLE | USD | 非空、有限正数 |
| `volume` | DOUBLE | BTC | 非空、`>= 0` |

推荐使用 Snappy 压缩和约 100,000 行的 row group。文件名固定，版本通过 SHA-256、覆盖起止时间和生成记录区分。

## 时间与聚合

- `1m/15m/30m/1h/2h/4h/1d` 按 Unix UTC 固定秒数向下取整。
- `1w` 从 UTC 周一 `00:00:00` 开始。
- `1M` 从每月 UTC 1 日 `00:00:00` 开始，不按固定 30 天计算。
- 聚合值为首个 `open`、最大 `high`、最小 `low`、最后 `close` 和 `volume` 求和。
- 数据缺失分钟保持缺口，不前向填充、不插值，也不生成模拟 K 线。

## 启动校验

行情服务在监听端口前必须验证：

1. 文件存在且可读取。
2. 六个必需列存在且类型匹配。
3. 至少存在一条有效记录。
4. 记录排序和去重后仍满足 OHLC/volume 基本约束。

校验失败时容器退出非零，由 Compose 重启策略和运维告警处理；不得静默切换到内嵌演示数据。

## 数据构建与替换

- 数据获取脚本输出临时文件，完整校验后再原子重命名为目标文件。
- 生产替换前保留当前文件和 SHA-256；替换后重启行情服务并检查 `/api/market/meta`。
- 回滚时恢复旧文件并重启，不需要数据库迁移。
- 数据来源、产品代码、获取时间、覆盖范围、缺失桶数和 SHA-256 写入同目录的 `manifest.json`。

## 扩展路径

当单文件扫描或启动内存超过目标时，按 `symbol/year/month` 分区并引入清单索引。分区只是行情服务内部变化，公网 API 不变。M1 不提前引入对象存储或查询引擎。

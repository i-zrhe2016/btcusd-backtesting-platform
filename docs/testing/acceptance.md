# 测试与验收标准

## 文档阶段门槛

- 根 README 仅作为索引，详细说明全部位于 `docs/`。
- 所有内部链接有效，术语、服务名、端口和路径一致。
- 每张图同时包含 `.puml` 源码和经过渲染校验的 SVG。
- API 示例与数据库、Parquet 和服务边界文档一致。
- 文档评审通过前不继续实现或部署。

## Market Data

- 使用包含重复、缺失分钟和月/周边界的固定 Parquet fixture。
- 校验必需列、类型、空值、OHLC 约束和空文件失败。
- 覆盖 9 个周期的桶起始、OHLCV 聚合、左闭右开范围和最新 `limit` 截断。
- Stoch 覆盖预热 `null`、平盘为 50、不同长度和平滑结果。
- 相同文件和请求必须返回字节语义等价的数值结果。

## Backtest

- 覆盖买入、卖出、零交易、未平仓、手续费、胜负交易和最大回撤。
- 校验所有输入边界、无行情、指标未对齐、行情超时和非 2xx 响应。
- 数据库集成测试验证 `running → completed` 与 `running → failed`，以及用户过滤。
- 固定数据集的收益、交易数和交易时间戳作为回归基准。

## Web

- 375、768、1024 和 1440 像素宽度无横向滚动。
- 键盘可完成筛选和回测；焦点可见且不被粘性区域遮挡。
- 图表加载、空数据和错误状态均有文字反馈及重试操作。
- OHLC 表格与当前图表数据一致，涨跌不只用颜色表达。
- 减少动态效果模式下功能完整；正常文本对比度至少 4.5:1。

## 部署

- `docker compose config` 无错误，除 Nginx 外无宿主机端口。
- 全新 volume 可自动迁移并写入访客用户。
- HTTP 重定向 HTTPS，证书、HSTS 和安全头正确。
- 替换无效 Parquet 后行情容器拒绝就绪；恢复文件后可恢复。
- PostgreSQL 备份可在新 volume 恢复并复现基准回测。

代码构建、单元测试、数据库集成测试、前端点击验收、Compose 冒烟和安全检查全部通过；文档与实际 API 无差异。M1 完成不代表旧客户端退役，只有 M2 迁移矩阵全部通过后才能宣布功能等价。
